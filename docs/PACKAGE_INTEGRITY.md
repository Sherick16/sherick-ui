# Phase D — library and package integrity

## Result

**Complete for the current prerelease contract.** The implementation at `87275da` passed the
full `bun run verify` from a fresh `git archive` snapshot with a frozen dependency install.
No registry release was made, and this does not declare the alpha API stable.

## Public surface

Exactly five subpaths remain:

| Import | Contract |
| --- | --- |
| `sherick-ui` | Canonical core components, helpers and public types; ESM and CommonJS |
| `sherick-ui/content` | `Markdown`, `CodeBlock`, `MarkdownProps`, `CodeBlockProps`; ESM only |
| `sherick-ui/dev` | Common visual recipes, motion recipes and `cn` for the repository workbench; ESM/CJS, intentionally published but unstable and unsupported for consumers |
| `sherick-ui/styles.css` | Complete, precompiled, scoped component/theme/motion/accessibility/rich-content styling |
| `sherick-ui/theme.css` | Token-only light/dark/system theme output |

Host/framework CSS loads before `styles.css`. Consumers need neither Tailwind nor Base UI imports.
Document `dir` and the public `DirectionProvider` supply direction. Document-level `--sui-*`
overrides reach portals; isolated nested theme islands remain unsupported. Content dependencies
are installed normally but are excluded from core-only bundles. No aliases were restored.

## Defects corrected

- **CommonJS declarations:** one ESM `.d.ts` previously served both runtime formats, producing
  TS1471 for Node16 `.cts` consumers. Root/dev now have matching conditional `.d.ts`/`.d.cts`
  targets generated by Rollup. NodeNext alone would have missed this.
- **Missing public types:** exported `MenuTriggerProps` and `PopoverTriggerProps`; direct
  consumer imports compile. Runtime exports across all three JS subpaths are compared with
  declaration exports, and root/dev ESM exports are compared with CommonJS.
- **Prop targeting:** `Select.className` now merges with its visible button; Slider div
  attributes target its root instead of the thumb. Slider labeling and ref remain on the handle.
- **Hidden reset dependency:** the compiler now establishes border-box geometry, zero native
  borders, solid structural borders and neutral inherited form-control defaults only on
  explicitly owned nodes. Arbitrary host elements and consumer children are not normalized.
- **Global CSS names:** activity keyframes and KaTeX font families are prefixed, preventing host
  animation/font collisions without changing temporal recipes or the palette.
- **Hydration/DOM ownership:** Prism's automatic scan rewrote React-owned and unrelated host
  code markup before hydration. Its native manual mode disables that scan. Production Next
  hydration passes and the old showcase/rich-content error allowlists are deleted.
- **Publication hygiene:** source maps now embed their unpublished sources; copied math assets
  include the KaTeX license. Source/issue metadata is present. `prepack` replaces `prepare`,
  keeping the repository build at publication time rather than consumer installation.

## Dependencies and module boundaries

No runtime dependency was moved or added. The audit found the existing ownership truthful:
React/ReactDOM are peers, Base UI and directly imported utilities/icons are runtime dependencies,
and the rich stack belongs to `content` while remaining an ordinary installation dependency.
Tailwind and the library build tools remain development dependencies.

Clean npm dependency validation passed. The inspected React 19 tree deduplicated React,
ReactDOM and KaTeX through Base UI, the renderer and the rich stack; one Prism and one Base UI
version were installed. There was no demonstrated cost problem requiring a dependency reshuffle.

ESM imports and representative SSR run without browser globals on React 18.0.0 and 19.3.0.
CommonJS root/dev imports and Button SSR pass. `require("sherick-ui/content")` fails deliberately
with `ERR_PACKAGE_PATH_NOT_EXPORTED`; CommonJS dynamic import succeeds. Next renders passive
root components on the server while interactive/content leaf modules retain client boundaries.
There is no blanket client directive on the root barrel.

## Tarball review

The Phase D `sherick-ui-2.0.0-alpha.1.tgz` contained 279 files, 1,097,247 compressed bytes and
2,848,494 unpacked bytes. It includes ESM/CJS builds, five declaration artifacts, intentional
source-bearing maps, two CSS files, math fonts/license, package metadata, README and LICENSE.
No source tree, tests, fixtures, visual baselines, build scripts, tsbuildinfo or repository
configuration was included. Rich content has no misleading CJS build.

Phase E deliberately changes that packaging result to carry the Combobox accessibility fix to
consumers: the inspected artifact contains 4,129 files, 3,204,079 compressed bytes and 14,260,677
unpacked bytes. The additional files are exactly the bundled `@base-ui/react@1.8.0` package and its
runtime dependency closure, including their licenses and declarations; transient Bun store tags are
removed during staging. Sherick source, tests, fixtures and build scripts remain excluded. Application
bundle output is unchanged in kind and still passes the existing raw/gzip/brotli budgets; this is an
installation-artifact increase, not permission to raise a runtime size budget.
